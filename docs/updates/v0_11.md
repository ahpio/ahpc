# ahpc 0.11

> ## The good stuff
>
> ahpc reaches a host through a Dev Tunnel, VS Code's own included, and remembers how you start a session there.
>
> - [A host behind a Dev Tunnel](#tunnels): `--host tunnel:<id>` reaches ahpd or VS Code with no public port, signed in once with `ahpc tunnel login`.
> - [VS Code's tunnel](#tunnels): a VS Code agent host tunnel is reached through its gateway, and `--tunnel-host` picks the editor's host or a standalone one.
> - [The hosts screen](#the-screen): a page of what the host says about itself, with its agents and their models.
> - [Your last choice comes back](#the-screen): a new session starts with the agent, model and effort you used last on that host.
> - [Protocol 1.1.0](#connection): ahpc speaks the newest Agent Host Protocol, and older hosts still connect.

## 0.11.0 - 2026-11-18

### Upgrading

- A new session starts with the agent, the model and the model's options, such as effort, of the last session on the same host. `--no-remember`, or `"rememberChoices": false` in the config file, starts at the host's first agent and default model. See [New session](../use/NEW-SESSION.md#the-agent).
- A new session starts on the host's first agent until you pick one. It started on `claude`, which a host with no `claude` agent refused.
- The stage, unstage and discard dialog reads All files, This file, Cancel. This file still has the focus.

### Tunnels

- `--host tunnel:<id>.<cluster>` reaches a host behind a Dev Tunnel, on port 31546, with no public port and no `devtunnel` CLI. An anonymous tunnel takes your own token; a private one takes a connect token from `--tunnel-token` or `AHPC_TUNNEL_TOKEN`. See [Connect](../start/CONNECT.md#a-host-behind-a-dev-tunnel).
- `ahpc tunnel login` signs in to Dev Tunnels with a code from GitHub, `ahpc tunnel list` shows the tunnels with an agent host, and `ahpc tunnel logout` forgets the sign-in.
- Signed in, `--host tunnel:<id>` needs no cluster and no connect token.
- ahpc asks for a fresh connect token on each connection, so a reconnect the next day still gets in.
- `--tunnel-access` or `tunnelAccess` picks the way in: `auto`, `anonymous` or `signed-in`. `auto` signs in when the tunnel asks for it.
- A VS Code tunnel at protocol 6 is reached through its gateway. `--tunnel-host` or `tunnelHost` picks the editor's agent host or a standalone one, on a tunnel that offers both.
- A connect token the tunnel refuses is named as the connect token, and ahpc stops at once.
- A failure message ends in one period, not two.
- A run against a host that never answers a WebSocket close, as VS Code's gateway does, ends when its work is done.

### The screen

- **Show hosts** in the palette opens the hosts screen. See [Host](../use/HOST.md).
- It shows the connection, the server, the machine, the automations, the agents, the settings, the trusted folders and the terminals.
- A section the host sent nothing for is not drawn.
- Enter or a click on an agent opens its models.
- `n` starts a new session with the selected agent, and with the selected model.
- The sign-in prompt sends a token once, however Enter is pressed.
- On the changes screen, the arrows step past a tab that needs a turn.

### Connection

- ahpc speaks Agent Host Protocol 1.1.0, and offers 1.0.0 and older behind it.
- A failure that the host explains in a short sentence quotes it.

### Commands

- `ahpc automation` gains `new`, `edit`, `duplicate`, `export` and `import`. See [Automations](../subjects/AUTOMATIONS.md).
- A still against a live host waits for the host to answer before it draws.

### Docs

- *Use* has a page for each screen, with a picture drawn from ahpd's demo host.
- The new-session page says which fields the host serves.
